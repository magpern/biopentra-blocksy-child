# Biopentra Blocksy Child 1.4.0 — release notes

All changes in this release are scoped to Checkout v2, gated behind the
existing `biopentra_checkout_v2_enabled` option (already **on** in prod) or
the `?checkout_v2=1` preview flag — same pattern as My Account v2.

## Added

- **Inline coupon-code field.** A compact "Coupon code" input + Apply
  button now sits directly in the order-review table, between the
  Subtotal/Shipping rows and Total — Blocksy's theme setting had removed
  WooCommerce's default coupon form site-wide, so there was previously no
  way to enter one at checkout at all.
- **Gift card / store credit** panel (from `mp-commerce-promotions`)
  relocated from a full-width box above Billing Details to a small,
  left-aligned link directly under the coupon field — same information,
  far less vertical space, especially on mobile.
- **Checkout banner.** Replaces the plain left-aligned "Checkout" page
  title and the old plain-text trust strip with a single centered banner
  image (shield icon, "Secure Checkout" headline, and the same
  secure/EU-fulfillment/fast-processing trust points as icon badges).
  The real `<h1>Checkout</h1>` stays in the DOM off-screen (not removed)
  for SEO/screen readers. Cropped to its left portion on mobile instead
  of scaling the whole (wide, fixed-aspect) image down to illegible size.

## Fixed

- **Coupon silently reapplying itself a few seconds after removal.** Root
  cause: the coupon row's `<form>` was nested inside WooCommerce's own
  outer checkout `<form>` — invalid HTML that silently breaks native
  `submit` event bubbling in Chromium, so neither WooCommerce's own
  coupon-apply binding nor a delegated handler of ours ever fired once
  the row was regenerated by WooCommerce's own automatic post-load AJAX
  refresh. "Apply" fell back to a genuine full-page form POST, which
  WooCommerce's non-JS fallback processed server-side and redirected back
  from — looking exactly like the coupon reappearing on its own. Fixed by
  dropping the nested `<form>` for plain markup driven by delegated
  click/Enter-key handlers instead.
- The checkout banner now renders via a `the_content` filter instead of a
  `woocommerce_before_checkout_form` hook, so it reliably renders above
  other plugins' own `the_content`-injected content (e.g. a crypto-payment
  guide banner) regardless of hook-priority ordering inside the checkout
  form itself, where it could never have won.
- Collapsed an empty ~280px gap Blocksy's own page-title section left
  above the banner — the whole section is now hidden the same accessible,
  off-screen way as the title text within it, not just the text.

## Net-zero (no visible change)

- An in-progress 3-step Details/Delivery/Payment checkout wizard was
  built, iterated on, and then fully reverted per product decision mid-
  session — the checkout layout itself is unchanged from 1.3.0 aside from
  the additions above.

## Install

Deploy the `blocksy-child` theme **1.4.0** / tag **`v1.4.0`**.

No database changes. `biopentra_checkout_v2_enabled` is already `yes` on
prod, so all of the above goes live immediately on install — no option
flips or manual data steps needed. The banner image ships inside the
release ZIP (`assets/checkout-v2/images/checkout-banner.webp`).

Rollback: **1.3.0** / `v1.3.0`.
